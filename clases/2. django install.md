# Instalación de Django
## Comandos
```bash
Instalar carpetas env y crear el entorno virtual:
    python -m venv env	
Activar Entorno:
    Git:
	    source env/Scripts/activate	
    Windows cmd:
        env\Scripts\activate
Instalar Django:
	pip install django	
Crear Proyecto:
	python -m django startproject config .
Migraciones:
    python manage.py migrate
    python manage.py runserver
```
**Explicación de startproject**
`python -m` &rarr; Si en env nosotros instalamos la versión 5.0 de django nos aseguramos de usar solo esa versión, esto sirve para evitar conflictos de clases o funciones obsoletas

`config .` &rarr; Es el nombre que tendrá nuestra carpeta, por buenas prácticas siempre se le llama config, ya que van muchas configuraciones dentro.
El punto final mvita que Django cree una carpeta dentro de otra con el mismo nombre.

## Pasos

### 0. Modificar datos de idioma
En la carpeta config vamos a entrar al archivo settings.py, casi al final vamos a modificar esto:
```python
LANGUAGE_CODE = 'es-cl'

TIME_ZONE = 'America/Santiago'

USE_I18N = True

USE_TZ = True
```
### 1. Crear una "App"
Django organiza el código en "Apps". El proyecto es el contenedor general, pero la lógica vive en apps. Con el servidor detenido (Ctrl + C), escribe:

```bash
python manage.py startapp principal
```

Aparecerá una carpeta nueva llamada principal. Dentro hay archivos como `views.py`

### 2. Registrar la App
Django es muy ordenado; si creas algo, debes avisarle al proyecto que existe.

Abre la carpeta de tu proyecto (la que tiene el mismo nombre que tu carpeta raíz).

Busca el archivo `settings.py.`

Busca la lista llamada INSTALLED_APPS y agrega el nombre de tu app entre comillas al principio:

```Python
INSTALLED_APPS = [
    'principal',  # <--- Agregamos esto
    'django.contrib.admin',
    ...
]`
```

**Entendiendo la App**
Estos serpan los tres archivos que usaremos para el inventario:
models.py: Aquí definimos la Bodega. Diseñaremos cómo es un producto (nombre, precio, stock).

views.py: Aquí está el motor. Escribiremos la lógica que busca los productos para mostrarlos.

admin.py: Es una herramienta de Django que nos dará un panel de control automático para que los dueños del bazar puedan subir sus productos sin saber programar.

### 3. Crear la Vista
La vista es una función de Python que decide qué responder cuando alguien entra a la web.

Abre la carpeta principal y luego el archivo `views.py.`

Borra todo y escribe esto:

```Python
from django.shortcuts import render
from django.http import HttpResponse

def hola_mundo(request):
    return HttpResponse("<h1>¡Hola Clase! Este es nuestro primer Backend</h1>")`
```
- Request es la petición que viene del navegador. 
- El return es la respuesta que enviamos de vuelta.

### 4. Crear la "URL" 
Ahora hay que decirle a Django en qué dirección vive esa función.

Ve a la carpeta del proyecto y abre `urls.py.`

La cambiaremos para que se vea así:
```Python
from django.contrib import admin
from django.urls import path
from principal.views import hola_mundo # Importamos nuestra función
urlpatterns = [
    path('admin/', admin.site.urls),
    path('saludo/', hola_mundo), # <--- Si entran a /saludo/ verán el mensaje
]
```
### 5. La prueba final

Correr el servidor: python manage.py runserver.

En el navegador, ir a: [http://127.0.0.1:8000/saludo/](http://127.0.0.1:8000/saludo/).

- Abrir el Modo Inspeccionar (F12) -> pestaña Network.

- Recargar la página.

- Verán una petición que dice saludo/.

- El método es GET.

- El status es 200 OK.

En la pestaña "Response" del inspector, verán el código `<h1>` que escribieron en el archivo `views.py.`


### Resumen del Flujo de Datos:
Cuando todo está listo, el camino que sigue la información es:

**URL**: "¿A dónde quiere ir el usuario?"

**VIEW:** "¿Qué código debo ejecutar para esa dirección?"

**RESPONSE:** "Envía el resultado (HTML/Texto) de vuelta al navegador".
